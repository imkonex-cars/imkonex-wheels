# IMKONEX CARS · каталог и кабинет менеджера · 0.5.0

Готовая исходная сборка для репозитория **imkonex-cars/imkonex-wheels**. Обновление витрины сохраняет действующий импорт и фотографии. Пошаговая установка: [UPGRADE_v0.5.0.txt](UPGRADE_v0.5.0.txt). Подробности серверной части: [docs/MANAGER_RENDER.md](docs/MANAGER_RENDER.md).

В этой версии:

- Новый дизайн: графитово-зелёная палитра, светлый фон, крупный первый экран, реальные фотографии, карточки с ценой за штуку и комплект.
- Каскадный подбор: марка → модель → годы выпуска → модификация → товары, возвращённые штатным подбором API и присутствующие в нашей выгрузке.
- Поиск по артикулу/размеру/модели, размерные фильтры, бренды, сезон, избранное, сравнение, корзина и сохранение подбора.
- Категории по явным типам поставщика: легковые/SUV, грузовые/коммерческие, спецтехника, мото/квадроциклы, диски, камеры. Категория отображается только при наличии соответствующих товаров.
- В публичном интерфейсе убраны количество товаров, время выгрузки, поставщик и диагностические панели.
- Отдельный кабинет `/manager/`: закупка по складам, фиксированная розничная цена или наценка, разница закупки/продажи, формирование заказа и просмотр исполнения.
- Заказ сначала проверяет цены и остатки, затем требует отдельного подтверждения. Результат отправки сохраняется в постоянную базу; повторный запрос не создаёт второй заказ.

## Два режима размещения

| Режим | Возможности | Настройка |
|---|---|---|
| Текущий Render Static Site | Новый дизайн, каталог, размерные фильтры, избранное, сравнение, корзина | `node BUILD_RENDER.mjs`, публикация `dist` |
| Render Web Service | Вся витрина, API подбора по автомобилю, кабинет, серверные цены и заказы | `Dockerfile.portal`, постоянный диск `/var/data`, параметры доступа в Render Environment |

На Static Site кнопка подбора по автомобилю предлагает помощь менеджера. Закрытый кабинет и живые запросы API выполняются серверной версией. Веб-сервис отдаёт витрину и API с одного адреса. Цены из кабинета действуют именно на этом адресе; отдельный старый Static Site продолжает показывать цены своей выгрузки.

**Рекомендуемые начальные ресурсы:** 1 vCPU, 2 ГБ RAM, постоянный диск 1 ГБ. Выберите платный план с такими параметрами в Render. Стоимость показывается при создании сервиса. `render-manager.yaml` — отдельный Blueprint, он не запускается от одной загрузки файла в GitHub.

## Установка

1. Для уже работающего репозитория используйте архив `IMKONEX_PREMIUM_UPDATE_v0.5.0.zip`. Загрузите его распакованное содержимое в корень репозитория с заменой совпадающих файлов. Текущие `data/` и фотографии этот архив не заменяет.
2. Дождитесь зелёной проверки GitHub и сборки Static Site. Команда остаётся `node BUILD_RENDER.mjs`, публикация `dist`, Root Directory пустой.
3. Для полной функциональности создайте новый Web Service с Dockerfile `./Dockerfile.portal`, диском `/var/data` и переменными из инструкции.
4. Откройте **новый адрес сервиса**, затем `/manager/` и проверьте закупку одного артикула.
5. Запустите существующий workflow импорта, чтобы получить явные типы товаров и камеры.

Полная сборка `IMKONEX_WHEELS_WORKSPACE_v0.5.0.zip` нужна для восстановления или нового репозитория. Она включает публичную выгрузку из 20 359 товаров от 22.09.2026 и имеющиеся изображения. Не заменяйте ею более свежую выгрузку при обычном обновлении. Корень архива является корнем репозитория. Файлы перечислены в `FILES_MANIFEST.txt`.

## Кабинет и заказы

Доступен один общий аккаунт менеджера. Логин задаёт `MANAGER_LOGIN`, пароль — `MANAGER_PASSWORD` (от 12 символов). Пользователи, роли и двухфакторная аутентификация в эту версию не входят. Сессия действует 8 часов; смена логина/пароля отзывает прежние сессии после перезапуска.

Фиксированная цена действует на выбранный артикул. Наценка рассчитывается от закупки **каждого склада**, с минимумом в рублях и округлением вверх до 10 ₽. Закупка для сохранённых наценок обновляется при старте и раз в 6 часов. Если источник не отвечает более суток, предложение с такой наценкой скрывается до получения свежей закупки. Кнопка обновления в кабинете запрашивает закупку отображаемых товаров.

`SUPPLIER_ORDERS_ENABLED=false` первоначально запрещает отправку. После проверки доступа можно установить `true`. Флажок «Тестовый заказ» соответствует `is_test=true`: он **создаёт запись у поставщика** в статусе «я формирую». Снятый флажок отправляет боевой заказ с резервированием. Доставка оформляется отдельно; её стоимость не включена в показанную сумму закупки. Платежи и выдача чеков здесь не реализованы.

При таймауте результат может быть неизвестен. Повторная отправка заблокирована: менеджер сверяет уникальный номер `IMX-…`, артикулы и количества в кабинете поставщика и связывает найденный заказ по ID. История отображает состояния, прочитанные нашим кабинетом, а не полную историческую ленту поставщика до подключения.

## Данные и границы проверки

Полная текущая выгрузка сохранена. Новые типы и камеры появятся после **успешного следующего импорта** и только если доступны вашему аккаунту. Товары с неизвестным типом остаются в «Все шины». Размеры, категории, фото и сроки не придумываются. Для грузовых/спецшин поддержаны более широкие диапазоны параметров, неизвестные значения остаются пустыми. Неподдержанные записи учитываются в закрытом отчёте импорта.

Код проверен автоматическими тестами с синтетическими ответами, включая реальные ранее полученные схемы запросов подбора. Новые запросы подбора, расширенного импорта и создания/чтения заказов с вашей учётной записью **в этой среде не выполнялись**. Боевые заказы не отправлялись. Браузерный визуальный просмотр локальных файлов был заблокирован средой; итоговый вид нужно оценить после публикации. Сайт 74kolesa.ru при изучении не предоставил страницу; интерфейс разработан самостоятельно, без утверждения о визуальном сравнении с его текущей версией.

## Проверка и структура

```sh
npm ci
npm test
node BUILD_RENDER.mjs
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

- `frontend/` — витрина, стили, изображения; `frontend/manager/` — интерфейс кабинета.
- `backend/portal.py` — сервер, сессии, правила цен и операции кабинета.
- `backend/portal_supplier.py` — адаптер SOAP с проверкой схемы и единственной операцией создания заказа.
- `backend/portal_store.py`, `portal_jobs.py` — постоянная база и обновление закупки для наценок.
- `backend/catalog_sync.py`, `catalog_types.py` — полный импорт и явные категории.
- `data/supplier-snapshot.json` — только публичные сведения и розничные цены.
- `config/sync.json` — пределы импорта и включение камер/расширенных типов.
- `scripts/` — сборка, проверка публичного контракта, упаковка и резервное копирование.
- `tests/` — проверки контрактов, цен, остатков, интерфейса, авторизации и заказов.
- Старые `backend/app.py`, `render-api.yaml` и часть документации сохранены для совместимости с предыдущим прототипом. Для версии кабинета используйте `backend.portal:app` и `Dockerfile.portal`.

Пароли, закупка и клиентские данные не входят в публичную выгрузку. `runtime/`, базы, локальные отчёты, `.env` и резервные копии исключены из сборки и архива. Для SQLite нужен постоянный диск; инструкция резервного копирования находится в `docs/MANAGER_RENDER.md`.

Официальные контракты: [подбор по автомобилю](https://b2b.4tochki.ru/Help/Page?url=GetGoodsByCar.html), [типы шин](https://b2b.4tochki.ru/Help/Page?url=object/FindTyreFilter.html), [камеры](https://b2b.4tochki.ru/Help/Page?url=GetFindCamera.html), [создание заказа](https://b2b.4tochki.ru/Help/Page?url=CreateOrder.html), [состояние заказа](https://b2b.4tochki.ru/Help/Page?url=GetOrderInfo2.html). Размещение: [Render Web Services](https://render.com/docs/web-services), [постоянные диски](https://render.com/docs/disks).
