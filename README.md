# IMKONEX CARS · шины и диски

Версия 0.1.0 · 14 сентября 2026 года.

Рабочая демонстрация каталога для первого размещения в GitHub и на бесплатном Render. В комплекте есть статическая витрина, API на Python, схема PostgreSQL и конфигурация дальнейшего запуска на VPS.

**Это демонстрационный этап.** Все 72 артикула, варианты размеров, характеристики, цены, остатки и сроки синтетические. Фотографии иллюстрируют шесть реальных моделей. Реальная покупка, оплата и передача заказа поставщику отключены. База применимости к автомобилям не подключена.

## Посмотреть без установки

Откройте `IMKONEX_WHEELS_PREVIEW.html` из архива в современном браузере. Изображения и код встроены в файл. При ограничениях браузера на локальное сохранение используйте запуск через локальный сервер ниже.

## Что работает

| Раздел | Поведение |
|---|---|
| Шины и диски | 36 тестовых вариантов шин и 36 дисков, фотографии, карточки, предложения складов |
| Подбор | Зависимые размеры, сезон, бренд, цена, XL, RunFlat, шипы, наличие комплекта, срок |
| Поиск и выдача | Поиск по модели/артикулу/размеру, сортировка, страницы по 12 товаров, фильтры в URL |
| Избранное | Сохранение в браузере |
| Сравнение | До четырёх товаров одной категории, режим различий |
| Корзина | Количество, расчёт по одному складу, JSON-выгрузка, локальная тестовая заявка |
| Мой автомобиль | Сохранение введённого пользователем размера; применимость не подтверждается |
| Демо-кабинет | Локальные заявки, калькулятор наценки, честные состояния интеграций |
| API | Каталог, параметры фильтров, серверный расчёт, закрытый по умолчанию служебный endpoint |

В выбранных моделях нет примеров шипованных шин и RunFlat: соответствующие фильтры могут дать пустую выдачу. Города сохраняются как предпочтение; доставка вне Челябинска не рассчитывается. Любые сроки в демо условные.

## Быстрый локальный запуск

Нужны Node.js 22+ и Python 3.12. У витрины нет библиотек, необходимых для сборки: Node.js копирует и проверяет статические файлы.

```bash
npm run build
python3 -m http.server 4173 --directory dist
```

Откройте `http://localhost:4173`. В Windows команда Python может называться `python`.

Для API в другом терминале:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Документация API: `http://127.0.0.1:8000/docs`. Витрина этой версии использует встроенный демокаталог. `PUBLIC_API_BASE` подключает только проверку состояния API в кабинете, а не переводит каталог на реальные данные.

## GitHub → бесплатный Render

Подробно: [docs/RENDER.md](docs/RENDER.md).

1. Создайте **приватный** репозиторий `imkonex-wheels`. Загрузите содержимое папки проекта так, чтобы `package.json` и `render.yaml` находились в корне репозитория. Не загружайте `.env`, `.venv`, `node_modules`, резервные копии и реальные выгрузки поставщика.
2. В Render создайте Static Site из этого репозитория или Blueprint по `render.yaml`.
3. Build Command: `npm run build`. Publish Directory: `dist`. Node.js: `22`.
4. Render выдаст адрес сайта после успешной сборки. В этом пакете вымышленного адреса публикации нет.

Основной `render.yaml` создаёт только статический сайт: без базы, фонового сервиса и платного вычислительного инстанса. Статические сайты обслуживаются CDN; ограничения бесплатного web service относятся к отдельно запускаемому API. Действуют квоты аккаунта на трафик и сборки. [Render: Static Sites](https://render.com/docs/static-sites), [Render: бесплатные сервисы](https://render.com/docs/free).

## Следующий сервер

Для пилота с PostgreSQL и синхронизацией ориентир — **4 vCPU, 8 ГБ RAM, 120–160 ГБ NVMe**, Linux и Docker Compose. Это начальная оценка, а не обещание количества посетителей; нужна нагрузочная проверка на реальной выгрузке. Инструкция: [docs/VPS.md](docs/VPS.md).

## Что требуется для реальных продаж

1. Действующий доступ 4tochki и проверка актуальной схемы методов. Команда диагностики подготовлена, нормализация реального ответа ещё не реализована: [docs/FOURTOCHKI.md](docs/FOURTOCHKI.md).
2. Подтверждённая база применимости, правила выбора передней/задней оси и проверка дисков. Сейчас гараж — только сохранённый размер.
3. Серверное управление закупочными ценами и правилами розничных наценок. Демо-калькулятор не меняет витрину. Публичный API принимает только нормализованные розничные предложения.
4. Подключение интерфейса к реальному API, централизованные заявки, авторизация менеджеров, аудит действий, доставка и процесс подтверждения заказа. Демо-кабинет публичный; реальные данные в него помещать нельзя.
5. SEO-страницы товаров/категорий с серверным рендерингом или предварительной генерацией, карта сайта и канонические адреса. В этой версии hash-навигация и `noindex` намеренно подходят для прототипа.
6. Проверка прав на изображения и замена на разрешённые материалы поставщика. Источники и условия: [docs/ASSET_SOURCES.json](docs/ASSET_SOURCES.json). Лицензия на коммерческое повторное использование фотографий не подтверждена.

Интерфейс задаёт направление: фирменная тёмная шапка, компактный подбор, фотографии товара, прозрачный расчёт комплекта и адаптивные карточки. Превосходство над 74kolesa по скорости и удобству пока не измерено; для такого вывода понадобятся проверки в браузерах и замеры на опубликованных версиях.

| Путь | Назначение |
|---|---|
| `frontend/` | HTML, стили, интерактивная логика и изображения |

| `render-api.yaml` | Необязательный отдельный бесплатный API |

| `scripts/standalone.mjs` | Генерация автономного HTML-предпросмотра |

Паролей, токенов доступа, реальных закупочных цен и персональных данных в проекте нет. Логотип взят из предоставленного материала IMKONEX CARS, с сохранением пропорций.
