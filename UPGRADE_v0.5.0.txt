ШАГ 1. ОБНОВИТЬ КОД В GITHUB

Для работающего проекта используйте IMKONEX_PREMIUM_UPDATE_v0.5.0.zip.
Распакуйте архив. Загрузите СОДЕРЖИМОЕ его корня в корень репозитория
через Add file → Upload files. Сохраняйте вложенные папки.
Подтвердите Commit changes. Удалять все файлы репозитория не нужно.
Архив обновления не содержит data/ и фотографий: действующая выгрузка останется.

README.md, BUILD_RENDER.mjs, Dockerfile.portal, render-manager.yaml должны
лежать рядом с package.json, а не внутри дополнительной папки архива.
Если новая папка manager не появилась, проверьте frontend/manager/index.html.

Файл .github/workflows/ci.yml входит в обновление. Если его неудобно
перетащить, откройте существующий файл в GitHub и замените содержимое
текстом из файла архива. Существующий sync-catalog.yml сохраняется.

ШАГ 2. ПРОВЕРИТЬ НОВУЮ ВИТРИНУ

В существующем Render Static Site настройки остаются:
Root Directory — пусто
Build Command — node BUILD_RENDER.mjs
Publish Directory — dist

Запустите Manual Deploy → Deploy latest commit, если сборка не началась сама.
В журнале будет BUILD_OK IMKONEX-WHEELS-0.5.0-WORKSPACE-1.
Откройте сайт и нажмите Ctrl+F5. Новый первый экран: «Уверенность в каждом повороте».
Подписи о поставщике, количестве товаров и дате выгрузки исчезнут из интерфейса.

ШАГ 3. ЗАПУСТИТЬ СЕРВЕР ДЛЯ КАБИНЕТА И ПОДБОРА ПО АВТО

Static Site не выполняет Python и не хранит закрытую базу кабинета.
Создайте отдельный Render Web Service из ТОГО ЖЕ репозитория:

New + → Web Service → imkonex-cars/imkonex-wheels
Name: imkonex-wheels-portal (или свободное похожее имя)
Branch: main
Language / Runtime: Docker
Root Directory: пусто
Dockerfile Path: ./Dockerfile.portal
Docker Build Context: .
Docker Command: пусто (уже задан в Dockerfile)
Health Check Path: /health
Instances: 1

Рекомендуется 1 vCPU и 2 ГБ RAM. Это платный сервис.
Точную стоимость выбранного плана Render покажет перед созданием.
Добавьте постоянный Disk: Mount Path /var/data, Size 1 GB.
Диск доступен на платных сервисах. Он хранит цены, заказы и сессии.

Environment — добавьте:
MANAGER_LOGIN = manager
MANAGER_PASSWORD = придумайте отдельный пароль длиной от 12 символов
MANAGER_DB_PATH = /var/data/manager.sqlite3
FOURTOCHKI_LOGIN = ваш логин API
FOURTOCHKI_PASSWORD = ваш пароль API
SUPPLIER_ORDERS_ENABLED = false

Вводите настоящие пароли только в Render Environment.
GitHub Secrets не переносятся в Render автоматически.
Не добавляйте LOCAL_DEV=true на публичном сервере.

Альтернатива ручной настройке: New + → Blueprint и файл render-manager.yaml.
Укажите именно этот путь, а не стандартный render.yaml, который относится
к старому Static Site. Проверьте план и постоянный диск перед созданием.

ШАГ 4. ОТКРЫТЬ НОВЫЙ АДРЕС

После успешного запуска Render покажет адрес нового Web Service.
Откройте его: здесь будут и витрина, и подбор по автомобилю.
Кабинет находится по НОВОМУ адресу с добавлением /manager/.
Например: https://имя-вашего-сервиса.onrender.com/manager/
Это пример формата, фактический адрес возьмите в Render.

Старый Static Site не получает изменения цен из кабинета.
Проверяйте полную работу на новом адресе. После проверки можно подключить
нужный домен к новому сервису.

ШАГ 5. ПРОВЕРИТЬ КАБИНЕТ И КАТЕГОРИИ

Войдите логином manager и своим MANAGER_PASSWORD.
Цены и закупка → найдите известный артикул → Обновить закупку.
Первая загрузка схем API может занять время; если чтение не ответило,
повторите чтение позже. Пароль поставщика в браузер не передаётся.
Задайте фиксированную цену и проверьте её в новой вкладке витрины.
Наценка обновляет закупку при старте и раз в 6 часов.

В GitHub откройте Actions → Sync 4tochki catalog → Run workflow.
После успешного импорта новые категории появятся, если есть такие товары.
До этого действующая выгрузка будет работать с прежними товарами.
Если импорт завершится ошибкой, последняя успешная выгрузка сохранится.

ШАГ 6. ВКЛЮЧИТЬ ЗАКАЗЫ ПОСЛЕ ПРОВЕРКИ ДОСТУПА

В Render Environment измените SUPPLIER_ORDERS_ENABLED на true.
Сохраните и дождитесь перезапуска.
В кабинете добавьте товар с конкретного склада в «Новый заказ».
Сначала используйте флажок «Тестовый заказ».
Проверьте цены и остатки → подтвердите создание тестового заказа.
Тестовый заказ тоже создаётся у поставщика: статус «я формирую».
Снятый флажок означает боевой заказ с резервированием товара.
Доставка и оплата оформляются отдельно.

Если ответ о создании не получен, НЕ создавайте новый заказ для повтора.
Откройте созданную запись в «Заказы и исполнение» и сверьте её с кабинетом
поставщика по IMX-номеру, артикулам и количествам. При найденном заказе
можно привязать его ID и продолжать получать статусы.
