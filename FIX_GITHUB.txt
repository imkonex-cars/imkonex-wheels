ИСПРАВЛЕНИЕ ЗАПУСКА GITHUB ACTIONS · IMKONEX 0.4.0

Проверено 21.09.2026: в репозитории нет requirements-sync.txt,
а часть корневых файлов осталась от версии 0.3.0. Этот архив
восстанавливает файлы версии 0.4.0 и актуализирует адрес репозитория.

1. Распакуйте этот архив.
2. Откройте https://github.com/imkonex-cars/imkonex-wheels/tree/main
3. В корне репозитория нажмите Add file → Upload files.
4. Перетащите содержимое распакованной папки с сохранением вложенных папок.
   Существующие файлы удалять не нужно. ZIP-файл загружать не нужно.
5. Нажмите Commit changes в ветку main.
6. Убедитесь, что requirements-sync.txt появился рядом с package.json,
   а в package.json указано "version": "0.4.0".
7. Actions → Sync 4tochki catalog → Run workflow → main → Run workflow.
   Оставьте оба флажка выключенными. Создайте новый запуск после коммита.
8. При ошибке откройте первый красный шаг и пришлите последние строки.

Доступ к API должен быть сохранён в Secrets ЭТОГО репозитория:
FOURTOCHKI_LOGIN и FOURTOCHKI_PASSWORD.

Уже существующий .github/workflows/sync-catalog.yml менять для этой ошибки
не требуется. Файл ci.yml в архиве восстанавливает отдельную проверку
проекта; старый файл .github/workflows/ci без расширения GitHub не запускает.
Если скрытая папка не загружается через браузер, создайте файл по точному
пути .github/workflows/ci.yml через Add file → Create new file и вставьте
содержимое ci.yml из архива. Это отдельная проверка, не запуск импорта.

Предупреждение о Node.js 20 и уведомление Ubuntu 26 не являются причиной
ошибки "No file ... requirements-sync.txt". Этот архив исправляет состав
проекта; версии actions в workflow не меняются.

Render должен использовать этот же репозиторий и ветку main.
Build Command: node BUILD_RENDER.mjs; Publish Directory: dist.
До успешного импорта исходная выборка из 6 товаров остаётся ожидаемой.
