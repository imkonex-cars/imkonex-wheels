IMKONEX CARS — проверка выборки каталога «4точки», версия 1.3
17.09.2026

КАК ЗАПУСТИТЬ НА ПК 2

1. Распакуйте архив IMKONEX_4TOCHKI_CATALOG_CHECK.zip полностью.
2. Откройте папку, в которой лежит START_CATALOG_CHECK.cmd.
3. Дважды щёлкните START_CATALOG_CHECK.cmd.
   Если файл открывается в редакторе: введите в PowerShell cmd /c и пробел,
   затем перетащите START_CATALOG_CHECK.cmd в окно PowerShell и нажмите Enter.
4. Дождитесь загрузки схем API. Введите API-логин и API-пароль.
   Пароль при вводе не отображается. Артикул вводить не требуется.
5. После проверки откроется HTML-отчёт в браузере. Если он не открылся,
   откройте RESULT.html в новой подпапке results.
6. Прикрепите к переписке IMKONEX_4TOCHKI_CATALOG_REPORT.json из этой же
   подпапки results. Нужен сам файл, а не только текст окна PowerShell.

Для каждого запуска создаётся своя папка results/дата-время.
Предыдущие результаты сохраняются. Старую рабочую проверку 1.2 заменять не нужно.
На компьютере требуется Python 3.12+; необходимые библиотеки устанавливаются
внутри .check-venv. Активация окружения вручную не нужна.

ЧТО ПРОВЕРЯЕТСЯ

— Авторизация и список складов: GetWarehouses.
— Поиск шин и дисков: GetFindTyre и GetFindDisk, pageSize=5.
— Характеристики: GetGoodsInfo, до трёх найденных артикулов каждой категории.
— Цены и остатки: GetGoodsPriceRestByCode, точное совпадение кодов.

Обычный запуск выполняет 7 запросов после загрузки схем, максимум — 9.
Если страница 1 пустая, один раз проверяется страница 0. Схема API задаёт
тип номера страницы, но не описывает начало нумерации; эта ограниченная
проверка не означает подтверждения полной постраничной выгрузки.
Число товаров на странице ограничено пятью; полная загрузка ассортимента
не выполняется. Сохраняется reportedTotalPages из ответа поставщика.

Шины сопоставляются с tyreList/TyreContainer, диски — с rimList/RimContainer.
Проверка wheelList для колёс в сборе в этот комплект не входит.
Коды товаров сравниваются точно, без преобразования в числа: ведущие нули
сохраняются. Цена, остаток и склад объединяются по коду товара и ID склада.
Остатки разных складов не суммируются. Поле rest выводится как в API,
без предположения, означает ли предельное значение точное количество.
Поля price и price_rozn показываются только в локальном отчёте. Продажная
цена IMKONEX, валюта, наценка и сроки доставки этим тестом не назначаются.
Нулевые сроки из справочника складов не превращаются в обещание доставки сегодня.
Ссылка на фото показывается, если API вернул HTTPS-адрес известного фотохоста.
Доступность самой фотографии в этом тесте не проверяется.

РЕЗУЛЬТАТЫ

sample_verified — для выбранных шин и дисков получены характеристики и
складские предложения. Это не подтверждение подключения сайта или полной
выгрузки. Количество предложений с положительными rest и price_rozn
показывается отдельно.
partial — часть выборки пустая, отсутствуют характеристики/предложения
либо один из запросов завершился ошибкой. Подробности — в отчёте.
authentication_failed — API вернул код 30. Следующие запросы не отправляются.
mapping_required — схема изменилась или структура ответа требует настройки.
check_failed — соединение, загрузка схем или начальная проверка не завершены.

Логин и пароль не записываются в результаты. В отчёте есть коммерческие
цены поставщика; он предназначен для проверки подключения с владельцем.
Запросы используют проверяемое HTTPS-соединение с хостом API поставщика.
Заказы не создаются. Сайт на Render и каталог автомобилей не изменяются.
