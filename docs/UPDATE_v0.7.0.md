# IMKONEX WHEELS · 0.7.0

Обновление существующего магазина на REG.ru. Данные, фотографии, пароли и SQLite сохраняются. Основной режим — оформление заявки с подтверждением менеджером. Эквайринг не подключён; оплата на сайте не имитируется.

## Витрина

- Исправлен перенос полного подвала: все три офиса, адреса, телефоны, контакты и ссылки. Сохранены SVG-иконки шапки. Старый неполный кэш заменяется исправленным резервным вариантом.
- Постоянная навигация: все шины, легковые, грузовые, мото, спецтехника, камеры, диски, датчики, расходники, масла.
- Подбор по назначению. Грузовые: размер, тип, ось, нагрузка, камерность. Мото: размер, вид техники, ось, конструкция, камерность, скорость. Спецтехника: тип, размер, протектор, слойность, камерность, нагрузка. Масла: SAE, объём, состав, назначение, ACEA и API. Дополнительные поля работают по фактически переданным характеристикам.
- Разноширокие шины: передняя и задняя ось, отдельные размеры и выбор двух позиций по 2 шт.; необязательное совпадение бренда/модели. Склад должен иметь нужное количество; остатки разных складов не суммируются.
- Страницы доставки, оплаты, возврата, контактов и статуса заказа. Содержимое условий задаётся менеджером.
- Вращающееся колесо при загрузке каталога, API, кабинета, заявки и статуса. При ограничении анимации в системе вращение замедляется.
- Детальная карточка с изображением и техническими характеристиками сохранена. Значения шумности не преобразуются в вымышленные децибелы.

## Цены

Один серверный механизм применяется к витрине, подборкам, заявкам и предпросмотру закупки. Минимальная цена — закупка + максимум из 100 ₽ и заданного минимального дохода. Доход здесь — разница продажи и закупки до остальных расходов.

Режимы массовых правил: розничная цена `price_rozn`, скидка от неё, наценка к закупке. Для отдельных товаров/складов дополнительно доступны фиксированная цена и доход в рублях. Закупочная цена — `price`; отдельного третьего поля РРЦ в проверенной схеме API нет. Для масел, датчиков и расходников базовый режим — `price_rozn`; при конфликте приоритет имеет минимальный доход.

Приоритет: правило склада → товара → подкатегории шин → вида товара → общее → розница API. Минимальный доход действует всегда. Сначала менеджер видит предпросмотр массового изменения, затем применяет его отдельной кнопкой. Предпросмотр указывает проверенные предложения, исключения и срабатывания минимальной цены.

Скидка поставщика по группе = `(1 − сумма закупки / сумма розницы) × 100%`. Учитываются только свежие положительные цены предложений, имеющих остаток; это показатель проверенной выборки, а не обещание общей договорной скидки.

Без актуальной закупки или без розничной цены для режима РРЦ предложение не имеет публичной цены. Цены загружаются в приватную БД на сервере: весь каталог обновляется частями по 50 артикулов, цены старше шести часов обновляются заново. Пакетный проход ограничен 40 минутами, продолжение запускается через 15 минут; цены старше суток скрываются. Видимые позиции без цены дополнительно проверяются при открытии витрины. Источник API может задерживаться — состояние видно в кабинете.

## Заявки

Корзина → проверка цен/остатков → имя, телефон, город и способ получения → подтверждение → номер и персональная ссылка. Двойная отправка и повтор после сетевого сбоя не создают вторую заявку. Изменение цены до отправки требует новой проверки.

Заявка сохраняется в SQLite на томе сервера; деньги и товар автоматически не резервируются. Менеджер видит клиентские данные, артикулы, склады, количество, сумму и историю. Допустимые статусы: получена → подтверждена → комплектуем → готова/отправлена → получена; отмена до отправки. Изменения видны по персональной ссылке. Публичная страница не раскрывает имя, телефон или закупку. Держателю ссылки доступен состав заказа — не публикуйте её открыто.

Подготовка закупки переносит выбранные строки в существующий процесс предпросмотра и отдельного подтверждения отправки поставщику. Автоматические клиентские сообщения, платёжный шлюз и интеграция трек-номера перевозчика не включены. Статус покупательского заказа обновляет менеджер. `SUPPLIER_ORDERS_ENABLED` сохраняет прежнее значение.

## Данные и ограничения

Старые выгрузки схемы 3 не содержат назначения шин. Такие позиции остаются в «Все шины» и «Прочие шины» в правилах цен; размеры не используются для угадывания назначения. Для заполнения новых разделов нужна успешная расширенная синхронизация схемы 5 (`extended_categories`, `include_tubes`, `include_accessories`).

Каскад марка → модель → годы → модификация оставлен для легкового подбора по проверенным методам API. Отдельная база применимости грузовиков/мото/спецтехники не подтверждена; в этих разделах используется подбор по характеристикам, без вымышленной совместимости.

Технический контракт основан на предоставленном диагностическом отчёте API и скриншотах кабинета «4точки». Текущие страницы 74kolesa и справки API не удалось полноценно получить из среды подготовки (тайм-аут/503). Первая живая расширенная выгрузка должна успешно пройти в GitHub с доступом вашего аккаунта.
