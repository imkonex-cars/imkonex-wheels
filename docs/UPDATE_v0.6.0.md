# IMKONEX · обновление каталогов 0.6.0

Сборка подготовлена 22 сентября 2026 года. Установку на ваши серверы нужно выполнить по шагам ниже. В сборке проверены 129 Python-тестов, 29 JavaScript-тестов и 15 дополнительных тестовых сценариев. Сборка витрины прошла с 20 359 товарами из имеющейся выгрузки.

|---|---|
| `GITHUB_WHEELS` | Изменённые и новые файлы каталога шин для существующего репозитория `imkonex-cars/imkonex-wheels` |

Это пакет обновления существующего проекта. **Сохраните остальные файлы в GitHub.** В пакете намеренно отсутствуют действующая выгрузка `data/supplier-snapshot.json`, фотографии товаров и секреты: существующие файлы остаются на месте.

## 1. Обновить каталог шин через GitHub

Выполняется на ПК, в браузере.

1. Распакуйте `IMKONEX_UPDATE_v0.6.0.zip` через «Извлечь всё».
2. Откройте [нужный репозиторий](https://github.com/imkonex-cars/imkonex-wheels) и ветку `main`.
3. Выберите **Add file → Upload files**.
4. Откройте папку `GITHUB_WHEELS`. Перетащите **её содержимое** в GitHub. В корне репозитория должны оказаться `package.json`, `backend`, `frontend`, `scripts`, `tests`, `config`, `docs` и остальные файлы из пакета. Саму папку `GITHUB_WHEELS` загружать как вложенный раздел не нужно.
5. Введите сообщение `Update wheels catalog to 0.6.0` и нажмите **Commit changes**.
6. В **Actions** дождитесь успешного выполнения **Verify catalog**. Если этот workflow уже есть в репозитории, он запускается от нового коммита автоматически.

Если GitHub показывает ошибку загрузки отдельного файла, проверьте, что выбираете распакованные файлы, а не сам ZIP.

## 2. Применить обновление на сервере шин

В Windows PowerShell:

```powershell
ssh root@168.222.194.250
```

После входа, когда строка начинается с `root@…`, выполните:

```bash
(
set -e
wheels backup
wheels update --include-code
curl --fail --silent --show-error https://wheels.imkonex.com/health
)
```

Ожидаемый ответ последней команды:

```json
{"status":"ok","version":"0.6.0"}
```

Команда обновления собирает новый Docker-образ, делает резервную копию базы менеджера перед переключением и ждёт успешной проверки контейнера. Пароли и действующая база находятся за пределами репозитория. Изменение таблиц базы добавляет новые поля, сохраняя цены и заказы.

Откройте [витрину](https://wheels.imkonex.com/) и [кабинет](https://wheels.imkonex.com/manager/). Выполните **Ctrl+F5**.

Если команда остановилась, получите состояние и последние сообщения:

```bash
wheels status
wheels logs
```

## 3. Загрузить датчики, масла и расходники

Категории уже добавлены в интерфейс. Товары появятся после успешной новой выгрузки вашего аккаунта поставщика.

1. В GitHub откройте **Actions → Sync 4tochki catalog**.
2. Нажмите **Run workflow**, выберите `main`.
3. Оставьте `dry_run` и `allow_large_drop` выключенными и запустите workflow.
4. Дождитесь успешного завершения. Расширенная выгрузка обходит доступные склады, поэтому может занять десятки минут.
5. На сервере шин выполните:

```bash
wheels update
```

Если ранее включён таймер обновления сервера, этот шаг также выполнится автоматически. Существующее расписание GitHub остаётся прежним.

Импорт использует `GetRest`, затем `GetGoodsInfo` и `GetGoodsPriceRestByCode`. Датчики распознаются по `pressureSensorList`, масла — по `oilList`, расходники — по `fastenerList`, `sparePartList` и расходным подтипам `cameraList`. Названия вымышленных методов и номера категорий не используются. В витрину попадают позиции с положительным остатком и розничной ценой.

Первая живая выгрузка этих разделов ещё не проверена вашим аккаунтом: из среды подготовки сервер API не ответил. Контракты взяты из вашего успешного диагностического отчёта. При ошибке, повторении страниц или нарушении структуры импорт сохраняет предыдущую рабочую выгрузку. В таком случае нужен текст ошибки **Download and validate the catalog** из Actions.

## 4. Как пользоваться новым кабинетом

Откройте **Цены и закупка**.

- Найдите товар по артикулу, бренду, модели или размеру. Доступны раздел, сезон, ширина, профиль, диаметр, PCD и минимальное количество.
- Разверните **Склады** и отметьте нужные. Выбор запоминается в этом браузере. «Снять все» исключает все склады из поиска.
- Закупка для открытой страницы подгружается автоматически, если её ещё нет или она старше суток. **Обновить цены и остатки** принудительно запрашивает текущую страницу. Первый запрос может занять больше времени из-за загрузки схемы API.
- **Обновить склады из API** получает названия, короткие обозначения, цвета и сроки из справочника поставщика. Пока справочник не получен, используются постоянные служебные цвета; сроки не придумываются.
- Нажмите мини-фото или название для просмотра фотографии, характеристик и предложений по складам. Если поставщик не передал изображение, показывается обозначение отсутствующего фото.

| Колонка | Значение |
|---|---|
| Цена поставщика / Закупка | Поле `price` API, закрыто от клиентов |
| Розничная цена 4точки | Поле `price_rozn` API; отдельная третья «рекомендованная» цена в вашем отчёте не обнаружена |
| Моя цена | Цена продажи IMKONEX за штуку |
| Наценка, % | `(Продажа − Закупка) / Закупка × 100` |
| Доход / шт., ₽ | `Продажа − Закупка` до доставки, налогов и других расходов |
| Маржа | Доход в процентах от цены продажи |
| Выбрать, шт. | Количество с конкретного склада |

Пример: закупка 5 000 ₽, наценка 20% → продажа 6 000 ₽, доход 1 000 ₽/шт., маржа 16,67%. Для четырёх штук доход составляет 4 000 ₽.

Измените **любое из трёх полей** — цену продажи, процент или доход в рублях. Остальные пересчитаются. Нажмите **Сохранить** в этой строке. Изменение только в поле ещё не меняет витрину.

Правило сохраняется отдельно для склада. При изменении закупки процентное правило пересчитывает продажу, правило дохода сохраняет заданную прибавку в рублях, фиксированная цена остаётся фиксированной. Новые правила в строках считаются до копеек. Старые общие правила сохраняют прежнее округление до 10 ₽. Индивидуальное правило склада имеет приоритет над общим правилом товара. Кнопка **Цена 4точки** переключает этот склад на розницу поставщика.

Количество, наценка и доход в рублях в строках относятся к конкретному предложению. Остатки разных складов не суммируются для обещания наличия одного комплекта.

## Подробная карточка для покупателя

При нажатии на фото или название шины открываются крупное изображение, цена и таблица характеристик: размер, сезон, нагрузка, скорость, шипы, усиление, RunFlat. Дополнительно из API запрашиваются шумность, сцепление, комфорт, устойчивость к аквапланированию, износостойкость, особенности протектора и другие переданные характеристики.

Данные подгружаются при открытии карточки, поэтому для их просмотра не требуется ждать полной повторной выгрузки. Успешный ответ кэшируется на сервере на сутки. При следующих полных выгрузках характеристики также сохраняются в публичной витрине. Закупочные цены этот запрос не возвращает.

Если конкретная характеристика не передана, указано «Нет данных». Значения шумности сохраняются в формате API: оценка без единицы измерения не превращается в выдуманное число децибел. Дополнительные характеристики доступны и в карточке менеджера.

## 5. Подборка клиенту

В кабинете:

1. Укажите количество у нужных товаров.
2. Сохраните изменённые цены.
3. Нажмите **Подборка клиенту** в нижней панели.
4. Выберите **Копировать текст** или **Копировать ссылку** и вставьте результат в ваш мессенджер.

Ссылка открывается без входа, действует семь дней и содержит название, фото, артикул, количество и зафиксированную цену продажи. Закупка, наценка и служебные данные в неё не включаются. Клиент также может распечатать подборку или сохранить её в PDF средствами браузера. Наличие и цена подтверждаются при оформлении.

На публичной витрине аналогичные кнопки находятся в корзине: **Копировать подборку** и **Ссылка на подборку**. На поддерживаемых устройствах доступно системное меню «Поделиться».

Для заказа поставщику нажмите **Добавить в заказ**. Существующие проверка остатков, предпросмотр, отдельное подтверждение и история заказов сохранены. Обновление само не включает отправку заказов, если она была выключена в настройках сервера.

## 6. Подключить общую шапку и подвал к каталогу автомобилей

Источник меню — опубликованная страница [основного сайта](https://www.imkonex.com/). Сервер шин проверяет её каждые пять минут. После публикации изменений новое меню появляется при следующем открытии/обновлении страницы обоих каталогов, обычно в пределах шести минут с учётом кэша. Если основной сайт временно недоступен, сохраняется последняя корректная версия.

В каталоге шин подключение уже входит в обновление. Для каталога автомобилей нужно один раз установить `CAR_MENU` **на его собственный сервер**, где расположен `/opt/imkonex-catalog`.

В Windows PowerShell замените `IP_СЕРВЕРА_АВТО` на адрес действующего сервера автомобильного каталога:

```powershell
$carMenuPath = Join-Path $env:USERPROFILE 'Downloads\IMKONEX_UPDATE_v0.6.0\CAR_MENU'
scp -r "$carMenuPath" root@IP_СЕРВЕРА_АВТО:/tmp/IMKONEX_CAR_MENU
ssh root@IP_СЕРВЕРА_АВТО
```

Если архив распакован в другое место, измените только `$carMenuPath` на фактическую папку `CAR_MENU`.

После подключения к серверу автомобилей:

```bash
(
set -e
python3 /tmp/IMKONEX_CAR_MENU/install_menu.py --check
python3 /tmp/IMKONEX_CAR_MENU/install_menu.py
cd /opt/imkonex-catalog
docker compose build web
docker compose up -d --no-deps --force-recreate web
docker compose ps web
)
```

Скрипт сначала проверяет ожидаемую структуру, создаёт резервную копию изменяемых файлов рядом с `/opt/imkonex-catalog`, затем добавляет подключение меню в публичные страницы и разрешение чтения меню/стилей с `wheels.imkonex.com` в CSP. Проверен на сохранённой сборке автомобильного каталога 5.7.20. При несовпадении структуры установка останавливается до записи файлов.

Откройте [каталог автомобилей](https://catalog.imkonex.com/) и обновите страницу через **Ctrl+F5**. Если каталог встроен в Tilda через iframe, используется шапка самой страницы Tilda — второй комплект меню внутрь iframe не добавляется.

Когда автомобильный проект обновляете из отдельного репозитория или архива, сохраняйте эти изменения исходников: `app/main.py`, дополнения в `static/index.html` / `static/truck-calculator.html`, два файла `static/imkonex-shared-menu.*`. Если будущая полная сборка их заменит, установщик можно применить снова после проверки структуры.

## Проверка результата

1. Витрина и `/health` показывают версию 0.6.0.
2. Шапка и подвал совпадают с опубликованным основным сайтом; пункты ведут на действующие разделы.
3. В кабинете видны закупка, розница, склады и поля пересчёта. Отключение склада меняет выдачу.
4. Сохранённая цена сохраняется после обновления страницы и используется в витрине/подборке.
5. Клиентская ссылка открывается в приватном окне без входа в кабинет и не показывает закупку.
6. После успешной выгрузки новые разделы содержат доступные вашему аккаунту товары.

Визуальная проверка новой сборки в настоящем браузере здесь не выполнена: инструмент браузера блокирует локальный адрес разработки. Проверены DOM-сценарии, API, расчёты, миграция базы, приватность подборки, импорт на тестовых ответах и сборка реальной имеющейся выгрузки. Финальная проверка отображения выполняется на ваших адресах после установки.
