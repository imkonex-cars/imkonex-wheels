# API первого этапа

Общий префикс не нужен: endpoint-адреса перечислены целиком. Интерактивная документация — `/docs`, схема OpenAPI — `/openapi.json`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Доступность каталога, режим demo/live, отключённые заказы |
| GET | `/api/products` | Фильтры, сортировка, страницы |
| GET | `/api/products/{id}` | Карточка с публичными розничными предложениями |
| GET | `/api/facets?kind=tires` | Значения параметров категории |
| POST | `/api/quote` | Пересчёт без сохранения заявки и без создания заказа |
| POST | `/api/orders` | Всегда 501 в этом выпуске |
| GET | `/api/admin/status` | Служебное состояние, требуется Bearer-токен |

Пример расчёта:

```json
{"lines":[{"id":"demo-001","quantity":4}]}
```

Клиент не передаёт цену. Сервер выбирает предложение с достаточным количеством на одном складе: сначала минимальный срок, затем минимальная цена. Если хотя бы одной позиции нет, возвращается 409 `INSUFFICIENT_STOCK`. Неверное количество, лишние поля и повтор одного артикула — 422.

Успешный ответ содержит `total`, `currency`, `items`, `mode`, `deliveryIncluded:false`, `fitmentConfirmed:false`, `orderCreated:false`. Ответ не резервирует товар и не подтверждает актуальность поставщика: в демо данные условные, в PostgreSQL актуальность зависит от импортированного снимка.

Служебный endpoint закрыт с 503, пока `ADMIN_API_TOKEN` пуст или короче 32 символов. После настройки принимает `Authorization: Bearer ...`. Токен не используется публичным демо-кабинетом и не должен попадать в JavaScript.

API пока не является полноценным сервером интернет-магазина. Нет аккаунтов покупателей, оплаты, централизованных заказов и управления товаром из кабинета. Полные карточки на статическом сайте остаются демонстрационными независимо от `DATA_MODE` сервера.
