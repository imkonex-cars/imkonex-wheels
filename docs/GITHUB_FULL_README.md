# IMKONEX CARS · полная сборка 0.3.0 для GitHub

Витрина с проверенной выборкой: 3 шины и 3 диска, розничные цены поставщика и остатки на 17.09.2026, 19:23 UTC. Полные исходники приложения, диагностики API и серверных заготовок находятся в SOURCE_CODE.zip. Автоматическая загрузка всего ассортимента и оформление заказа пока не подключены.

## Что загрузить в GitHub

В архиве **8 обычных файлов на одном уровне**:

| Файл | Назначение |
|---|---|
| index.html | Полная витрина: код, стили, логотип, данные 6 товаров |
| BUILD_RENDER.mjs | Самостоятельная сборка для Render с проверкой версии и целостности |
| package.json | Команды проекта; npm run build также запускает новую сборку |
| package-lock.json | Описание проекта без зависимостей для публикации |
| render.yaml | Настройки Static Site |
| README.md | Эта инструкция |
| START_HERE_PC1.txt | Короткая инструкция для ПК 1 |
| SOURCE_CODE.zip | Все исходники для дальнейшей разработки |

Распакуйте только внешний архив. SOURCE_CODE.zip загружайте как обычный файл: распаковывать его для публикации не нужно.

## Загрузка в существующий репозиторий

1. Откройте GitHub-репозиторий, подключённый к `imkonex-wheels-demo`. Проверьте совпадение ветки с полем Branch в Render.
2. Сохраните текущую копию через Code → Download ZIP.
3. В корне репозитория нажмите Add file → Upload files → choose your files.
4. Выберите все 8 файлов из распакованного архива и сохраните через Commit changes. Файлы index.html и BUILD_RENDER.mjs должны быть видны в корне.

Папки переносить не требуется. Новый вход сборки использует готовую витрину из index.html. Он не обращается к старому scripts/build.mjs и не перезаписывает данные демонстрационными товарами. [Загрузка файлов через GitHub](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

## Render

Откройте существующий сервис → Settings. Для полного пакета задайте:

| Поле | Значение |
|---|---|
| Тип сервиса | Static Site |
| Root Directory | Пусто: файлы находятся в корне репозитория |
| Build Command | **node BUILD_RENDER.mjs** |
| Publish Directory | **dist** |
| NODE_VERSION | 22 |

**Новая команда сборки обязательна.** Не оставляйте команду, которая напрямую запускает старые скрипты. Если указано npm run build, оно тоже работает с новым package.json, но явная команда выше позволяет однозначно проверить, какой файл выполняется.

В этом пакете данные уже встроены в index.html. CATALOG_MODE, PUBLIC_API_BASE и пароль API для публикации не требуются. Режим этой сборки фиксирован как snapshot. Наценка IMKONEX не применяется.

После изменения команды выберите Manual Deploy → Clear build cache & deploy. [Публикация и параметры ручной сборки Render](https://render.com/docs/deploys).

В журнале должны появиться:

```text
IMKONEX-WHEELS-0.3.0-FULL-1
Built dist: 6 products. Mode: snapshot. No client credentials.
BUILD_OK IMKONEX-WHEELS-0.3.0-FULL-1 | snapshot | 6 products
```

Если index.html и BUILD_RENDER.mjs окажутся из разных выпусков, сборка завершится понятной ошибкой до публикации. Загрузите все 8 файлов вместе. Если журнал содержит «72 demo products», выполняется прежняя команда или опубликован другой commit/репозиторий.

Откройте [каталог](https://imkonex-wheels-demo.onrender.com/) и нажмите Ctrl+F5. Вверху должно быть «Реальная выборка · 6 товаров», в подвале — «Сборка 0.3.0».

Откройте [сведения о сборке](https://imkonex-wheels-demo.onrender.com/build-info.json). Ожидаются version=0.3.0, mode=snapshot, products=6 и release=IMKONEX-WHEELS-0.3.0-FULL-1. Если вы создали другой сервис, добавьте /build-info.json к его адресу.

## Фотографии

Фото загружаются по ссылкам поставщика; нужен интернет. В этой среде доступность серверов изображений не подтверждена. При недоступном изображении появляется заглушка. Логотип и заглушка встроены в сборку.

Скрипты и стили опубликованной версии вынесены в файлы на том же домене и совместимы с script-src 'self' и style-src 'self'. Если существующий заголовок Content-Security-Policy ограничивает изображения только текущим доменом, в Render → Headers для пути /* замените его значением:

```text
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: https://api-b2b.pwrs.ru https://www.4tochki.ru; connect-src 'self' https://*.onrender.com; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'
```

render.yaml содержит эту политику, но для вручную созданного сервиса заголовок настраивается в панели Render. Не добавляйте вторую конфликтующую политику. [HTTP Headers for Static Sites](https://render.com/docs/static-site-headers).

## Исходники и воспроизведение

Для разработки распакуйте SOURCE_CODE.zip в отдельную папку. Там находятся frontend, backend, data, scripts, tests, конфигурации и документация. Не распаковывайте эти исходники поверх готового пакета публикации.

В каталоге исходников:

```text
python scripts/package-github.py
```

Нужны Python 3.12 и Node.js 22+. Команда заново собирает витрину, упаковывает исходники и выпускает плоский архив в artifacts/. Она не обращается к API поставщика. Для обновления товаров сначала используйте backend.export_snapshot с новым успешным отчётом 1.3.

Сам index.html можно открыть двойным щелчком на ПК 1. Для опубликованного сайта сборка создаёт dist с HTML, скриптами, стилями и build-info.json. Исходники, диагностические отчёты и старые файлы репозитория в dist не копируются.

Публикация в аккаунте пользователя из этой сессии не выполнена. Проверки пакета описаны в SOURCE_CODE.zip → docs/VALIDATION_0_3.md.
