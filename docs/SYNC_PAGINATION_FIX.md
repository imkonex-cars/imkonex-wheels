# Синхронизация 0.9.0-sync.2: пересекающиеся страницы

24 сентября 2026 года. Патч подготовлен на commit
`796f00eb41128d0c37661b8c5fe7d831b92af1d8` из `imkonex-cars/imkonex-wheels`.
В этом коммите уже есть нейтральное название магазина и компактные реквизиты,
но ещё нет ранее выданного исправления валюты камер.

## Что означает ошибка

`repeated_or_overlapping_search_page` означает, что загрузчик встретил
повторяющийся артикул внутри ответа либо артикул, уже полученный на предыдущей
странице этой категории. В указанном запуске это случилось при чтении шин,
после отметки 70/86 страниц; точную проблемную страницу старый журнал не сообщает.

По журналу нельзя установить, был ли повтор вызван изменением наличия,
перестановкой товаров между страницами или повторным ответом поставщика.
Сохранение предыдущего рабочего снимка при таком результате — ожидаемое поведение.

Старый порядок работы увеличивал интервал между поисковыми страницами:
после каждых 100 артикулов выполнялись два запроса подробностей по 50 товаров.
В sync.1 также сохранялись ранние страницы дисков до окончания обработки шин.

## Новое поведение

1. Ранние пробы всех включённых категорий проверяют формат и валюту;
   ответы этих проб отбрасываются.
2. Каждая категория полностью читается с начала, последовательными запросами
   поиска без `GetGoodsInfo` между ними. Все категории проходят эту стадию
   до загрузки подробных характеристик.
3. При пересечении страниц, изменении их количества или неожиданной пустой
   странице отклоняется вся попытка чтения категории. Категория читается
   заново, максимум **3 попытки**. Предыдущие строки и счётчики этой попытки
   не переносятся в новую.
4. Если выдача остаётся непоследовательной, импорт останавливается, сохраняя
   прежнюю публикацию. Артикулы не удаляются ради обхода проверки дубликатов.
5. Ошибки валюты, авторизации, схемы, цен и общего бюджета не запускают
   эти повторы. Все попытки используют один экземпляр клиента с общим
   лимитом запросов и времени.

В архив включено исправление ответа камер: `CurrencyRateItem`,
`ResultItems.GetFindCameraContainer`, чтение до успешной пустой страницы.
Проверка RUB на каждой непустой странице сохранена.

Строки поиска находятся только в памяти. Сырые SOAP-ответы, закупочные цены
и учётные данные не сохраняются в файлы патча или публичный снимок.

## Журнал

Новая первая строка шага выгрузки:

```text
IMKONEX_SYNC 0.9.0-sync.2: sequential search with bounded retries
```

Перед запуском также печатается commit исходников. `SYNC_RETRY` сообщает
о повторном чтении категории; это ещё не окончательная ошибка. Поля
диагностики: метод, категория, страница, число строк, повторов и пересечений,
ожидаемое/полученное число страниц, фаза и номер попытки.
Коды артикулов, цены и произвольные тексты поставщика в эту диагностику
не включаются.

При окончательной ошибке выводятся `SYNC_DIAGNOSTIC` и `SYNC_FAILED`.
При успехе — `SYNC_OK`, затем штатные проверка сборки и публикация снимка.

## Границы проверки

API поиска не предоставляет в изученной документации идентификатор
неизменяемого снимка или курсор. Последовательное чтение и контроль повторов
снижают риск и выявляют наблюдаемую несогласованность; это не гарантия
неизменности всех остатков в течение всего запуска. Цена и наличие
проверяются при оформлении заказа.

Авторизованная полная выгрузка в ходе подготовки патча не выполнялась.
Первый реальный запуск на вашей учётной записи — `dry_run=true` в GitHub Actions.

- [GetFindDisk](https://b2b.4tochki.ru/Help/Page?url=GetFindDisk.html).
- [FindTyreFilter](https://b2b.4tochki.ru/Help/Page?url=object/FindTyreFilter.html).
- [FindDiskFilter](https://b2b.4tochki.ru/Help/Page?url=object/FindDiskFilter.html).

Документация описывает нумерацию с нуля, `totalPages` и сортировку по цене
и остатку. Стабильная сортировка по артикулу не описана, поэтому параметр
`sort` не добавлялся. Размер страницы и текущие ограничения API сохранены.
