# Подключение массовой выгрузки 0.4.0

Короткие шаги для ПК1 и ПК2 одинаковые: START_HERE_PC1.txt в корне архива. Новый сервер или база данных для этого пилота не требуются. Текущая витрина остаётся Static Site на Render; обмен с поставщиком выполняет отдельный запуск GitHub Actions.

## Перед первым запуском

Обновите рабочий репозиторий содержимым архива. Файлы BUILD_RENDER.mjs, package.json, requirements-sync.txt и папки backend, config, data, frontend, scripts, tests должны находиться в корне. Новый workflow — .github/workflows/sync-catalog.yml. Для его ручного создания дана идентичная копия SYNC_CATALOG_WORKFLOW.txt.

Задайте FOURTOCHKI_LOGIN и FOURTOCHKI_PASSWORD через Settings → Secrets and variables → Actions → Secrets → New repository secret. Это доступ к API, который уже проверяли на ПК. Переменные Variables для пароля не используются.

Workflow запрашивает contents: write только для сохранения проверенного публичного снимка и фото. Если организация запрещает запись токеном Actions или основная ветка защищена от прямых коммитов, шаг git push остановится; каталог на Render не будет заменён этим запуском. Согласуйте разрешённый организацией способ записи или переносите подготовленный снимок через обычный процесс review. Не отключайте защиту ветки ради обхода правил.

## Два способа публикации Render

**Вариант A — существующий Auto-Deploy.** В Render проверьте подключение к imkonex-cars/imkonex-wheels, ветку main и Auto-Deploy → On Commit. Workflow записывает новый коммит. Проверьте, что Render действительно начал его сборку. Если этого не произошло, запустите Manual Deploy → Deploy latest commit, затем используйте вариант B для следующих выгрузок.

**Вариант B — Deploy Hook.** В Render откройте свой Static Site → Settings → Deploy Hook и скопируйте секретный URL. В GitHub Secrets добавьте RENDER_DEPLOY_HOOK_URL со всем этим URL. В Render переключите Auto-Deploy в Off, чтобы коммит и hook не запускали две сборки. Workflow вызовет hook только после успешного git push. После ручных изменений кода запускайте Manual Deploy в Render либо новый Sync 4tochki catalog. Код 200/202 означает принятие запроса, окончательный результат смотрите в журнале Render.

Официальные инструкции: [Deploy Hooks](https://render.com/docs/deploy-hooks), [размещение статических сайтов](https://render.com/docs/static-sites).

## Первый запуск

Actions → Sync 4tochki catalog → Run workflow → основная ветка main. Флажок dry_run оставьте выключенным, чтобы результат записался в рабочий снимок. allow_large_drop при обычном запуске также выключен.

Сначала выполняются тесты без доступа к аккаунту. Затем скрипт загружает схемы, проверяет форматы запросов, получает склады, обходит страницы шин/дисков и читает характеристики пакетами. Розничные цены и остатки берутся из GetFindTyre/GetFindDisk; GetGoodsInfo дополняет характеристики. Это данные на интервал выгрузки, а не непрерывный поток цен. Параметры начала и завершения записываются отдельно.

Логи содержат этапы, номера страниц и счётчики. Сырые ответы, закупочные цены и пароли не сохраняются. Итоговая сводка видна на странице запуска Actions. Статус snapshot_written означает подготовленный локальный снимок; фактическую публикацию подтверждают успешный git push, журнал Render и /build-info.json.

После публикации ожидаются version=0.4.0, dataScope=account_catalog и sync.complete=true. В интерфейсе — «Каталог поставщика» и время последней выгрузки. Перед первым успешным импортом dataScope остаётся verified_sample и отображаются 6 товаров от 17.09.2026.

## Автоматическое обновление

После первого успешного запуска создайте Repository variable CATALOG_AUTO_SYNC=true. Расписание задано в workflow: 23 2,14 * * * — 02:23 и 14:23 UTC / 07:23 и 19:23 Челябинск. При false или отсутствии переменной остаётся ручной запуск.

Запуски по расписанию могут задерживаться или пропускаться под нагрузкой GitHub; это не обновление строго в реальном времени. В публичном репозитории расписание может отключиться после 60 дней без активности. Смотрите [правила schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

После первого полного запуска оцените его длительность, расход минут Actions и сборок Render. Бесплатность при любом объёме не гарантируется: действуют [лимиты Render](https://render.com/docs/free) и тариф вашей учётной записи GitHub. Частоту увеличивайте после проверки ограничений запросов поставщика. До этого задан начальный интервал в 12 часов.

## Какие товары отображаются

Просматриваются обе категории, доступные учётной записи. По умолчанию запрашиваются все доступные склады. Для отбора складов измените warehouse_ids в config/sync.json; например, [2017] ограничит предложения складом «Челябинск 2». Это сужение ассортимента; после значительного изменения может сработать защита large_catalog_drop.

Публикуются предложения с положительными price_rozn и rest. Цена price не используется даже при отсутствии розничной. Некорректная цена или неизвестный склад прерывают импорт. Товары без поддерживаемых размерных характеристик исключаются со счётчиком, доступным в разделе «Проверка каталога». Неизвестный сезон показывается как «Сезон уточняется». Значения RunFlat, технологии диска и доставки не выводятся из неподтверждённых кодов.

Текущий формат поддерживает шины R/ZR с метрическими размерами 100–500 мм, профилем 15–100%, диаметром 10–30 дюймов, и диски в диапазонах проверенного публичного формата. Это не специализированный каталог всех грузовых/сельскохозяйственных/мотоциклетных размеров.

## Фото

Исходные шесть фотографий остаются локальными. Новые оригиналы кешируются по публичным ссылкам img_big_pish, затем img_big/img_small. Ссылки с учётной записью img_big_my для новой выгрузки не используются. Сохраняются только декодируемые PNG/JPEG/WebP до 2 МБ на файл. Не более 100 новых фото за запуск, 180 секунд на эту фазу, 100 МБ на общий кеш. Оставшиеся модели используют публичные ссылки поставщика. Недоступное изображение заменяется нейтральной заглушкой. Кеш будет пополняться последующими запусками; гарантии фото у каждого товара API не даёт.

## Ошибки и сохранение рабочего каталога

| Код | Что проверить |
|---|---|
| credentials_missing | Наличие двух GitHub Secrets и точное написание имён |
| authentication_failed | Действующий API-пароль и доступ учётной записи |
| supplier_unavailable / http_request_failed | Доступность API с GitHub runner, ограничения поставщика; повторить позже |
| response_array_changed / required_operation_missing | Изменение схемы или структуры ответа; нужен журнал без секретов |
| page_count_changed_during_scan / repeated_or_overlapping_search_page | Ассортимент изменился во время обхода либо изменились правила страниц; повторить позже |
| incomplete_or_duplicate_product_details | Не все запрошенные артикулы вернулись в GetGoodsInfo; снимок не заменён |
| currency_not_confirmed_rub / invalid_retail_or_stock | Неподтверждённая валюта, некорректные цены/остатки; нельзя автоматически подменять значения |
| large_catalog_drop | Число товаров уменьшилось более чем на 50% в категории; проверить причины, затем при подтверждённом изменении запустить allow_large_drop |
| empty_catalog_or_category | Пустая выгрузка или категория; рабочий снимок сохраняется |
| api_budget_exceeded / product_budget_exceeded / public_snapshot_too_large | Лимит пилота; оценить объём и пересмотреть архитектуру/параметры |
| public_contract_failed | Проверка публичного формата не пройдена; публикация остановлена |
| RENDER_DEPLOY_FAILED | Данные уже могли попасть в GitHub; проверить hook и запустить Render вручную |

Защиты не обещают свежесть старого снимка при сбое: дата в витрине сохраняется прежней. Через сутки показывается напоминание уточнить данные. Оформление реального заказа и оплата пока отсутствуют; отправка заявки менеджеру — отдельный следующий этап.

## Что уже подтверждено

Модуль проверен на синтетических ответах, сохранённых схемах и сопоставлении шести исходных реальных товаров с прежней публичной выборкой. Фактическую массовую выгрузку вашей учётной записи и запуск в GitHub нужно подтвердить первым запуском после ввода Secrets. Число артикулов заранее не выдумывается.
