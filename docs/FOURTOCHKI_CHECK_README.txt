IMKONEX CARS — проверка подключения к API «4точки»
Версия проверки 1.2 · 16 сентября 2026 года

Исправление 1.2: ответ success=true с error={code:null, comment:null}
больше не считается ошибкой. Подтверждённый ответ GetWarehouses содержит 41 склад.
Программа продолжает проверку указанного артикула после успешного ответа складов.
Явный success=false, непустой код/текст ошибки и SOAP-ошибки останавливают запросы.

Исправление 1.1: устранён ExternalReferenceForbidden при импорте связанных XSD.
Схемы разрешены только с api-b2b.4tochki.ru по HTTPS. Проверка сертификата,
запрет перенаправлений, DTD и XML-сущностей сохраняются.

Назначение
Это отдельная проверка доступа к поставщику, а не новая версия сайта.
Она получает схему API, запрашивает склады, а при указании артикула — сведения
о конкретном товаре и его ценах/остатках. Данные в каталог на Render не записываются.
Наценки и розничные цены программа не назначает. Ответы могут содержать закупочные цены.

Запуск в Windows
1. Распакуйте весь ZIP в обычную папку, например C:\IMKONEX-CHECK.
   Не запускайте START_CHECK.cmd прямо из окна архива.
2. Нужен установленный Python 3.12 или новее. Если его нет, используйте
   официальный установщик: https://www.python.org/downloads/windows/
   При установке включите Add python.exe to PATH.
3. Дважды нажмите START_CHECK.cmd. Права администратора не нужны.
   При первом запуске устанавливается zeep и его зависимости из PyPI
   в отдельную папку .check-venv рядом с программой.
4. Дождитесь загрузки схем API (до 3 минут). Если соединение не установится,
   программа сразу сохранит отчёт, не запрашивая пароль.
5. Если схема авторизации распознана, введите выданные «4точки» логин и пароль API.
   Это доступ API, а не пароль от GitHub или Render.
   При вводе пароля на экране нет символов — это нормально. Нажмите Enter.
6. По желанию введите один артикул поставщика из B2B-кабинета.
   Не используйте артикул demo-001 из нашей демонстрации.
   Если артикул пока неизвестен, нажмите Enter: будут проверены только склады.
7. Рядом с START_CHECK.cmd появится IMKONEX_4TOCHKI_REPORT.json.
   Пришлите этот JSON в текущий чат для проверки схемы и ответов.
   Пароль программа не сохраняет. Сам отчёт может содержать цены поставщика;
   не публикуйте его в открытом GitHub или на сайте.

Результаты
check_failed — не загрузилась схема API; смотрите error.type в отчёте.
mapping_required — схема получена, но параметры нужно сопоставить вручную.
request_failed — авторизованный запрос завершился транспортной или SOAP-ошибкой.
provider_error — поставщик вернул явное поле ошибки; дальнейшие запросы остановлены.
responses_received — ответы получены; это ещё не подтверждение правильности
товарных данных, доступа к ценам или работы всей витрины. Их проверим по содержимому.

Если метода или параметра нет в актуальной схеме, программа его не выдумывает:
сохраняет описание и отмечает необходимость сопоставления.
В отчёт включены до трёх примеров из каждого списка; это не полная выгрузка.
Реальная проверка обоих типов товаров требует отдельно проверить артикул шины
и артикул диска. Для второго артикула можно запустить программу ещё раз;
предварительно переименуйте первый JSON, чтобы сохранить оба результата.

Другие способы запуска
В корне распакованного пакета:
python -m pip install -r requirements-check.txt
python -m backend.supplier_check

Только схема, без авторизации:
python -m backend.supplier_check --no-auth

Для серверного запуска поддерживаются переменные окружения
FOURTOCHKI_LOGIN и FOURTOCHKI_PASSWORD. Не записывайте пароль в командную строку,
в репозиторий или в JavaScript сайта. Без переменных программа спросит его локально.

Границы проверки
Разрешены только запросы GetWarehouses, GetGoodsInfo и GetGoodsPriceRestByCode.
Методы создания, оплаты, резервирования и изменения заказов не вызываются.
Запросы отправляются только по HTTPS на api-b2b.4tochki.ru;
переадресация на другой адрес запрещена, проверка сертификата включена.

По состоянию на 16.09.2026 из среды подготовки программы HTTPS-запросы WSDL/XSD
завершались таймаутом или ошибкой соединения. Пароль поставщику отсюда не отправлялся.
Код проверен локальными автоматическими тестами, включая воспроизведение
ошибки версии 1.0, загрузку связанных XSD настоящим парсером Zeep,
блокировку других хостов и локальных файлов и запрет DTD/XML-сущностей.
На компьютере пользователя первая схема загрузилась; дальнейший импорт
блокировала настройка версии 1.0. Эта ошибка исправлена в версии 1.1.
Полученный пользователем ответ GetWarehouses подтвердил авторизацию и доступ
к 41 складу. Версия 1.1 ошибочно пометила пустой объект error как отказ;
это исправлено в 1.2 и проверено тестом на полученном ответе.
Проверка реального товара YSTX5R1510, его цен и остатков ещё не завершена.
